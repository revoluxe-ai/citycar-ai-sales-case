# CityCar — анализ отдела продаж

Тестовый кейс для позиции AI Automation Engineer / AI Agent Developer.

Сценарий: руководитель просит проанализировать работу отдела продаж за последние 30 дней. Источники — amoCRM и записи звонков.

[Ответ на шесть вопросов](docs/answers.md) · [Архитектура](docs/architecture.md) · [Реальный AI-кейс WB SKY](docs/wb-sky-ai-case.md)

## Что можно запустить

В репозитории реализована проверка текущего состояния сделок: отсутствие открытых задач и наличие просроченных задач.

Есть два режима:

- demo — учебные данные, доступ к CRM не нужен;
- live — чтение сделок и задач через amoCRM API v4.

Полный отчёт за 30 дней, распознавание звонков и LLM-анализ описаны в архитектуре. Они не подключены к реальным системам в этом примере.

## Быстрая проверка

Нужен Python 3.11 или новее. Внешних зависимостей нет.

```bash
git clone https://github.com/revoluxe-ai/citycar-ai-sales-case.git
cd citycar-ai-sales-case
python -m citycar_case --demo
python -m unittest discover -s tests -v
```

В демо должны быть найдены сделки 1001, 1002, 1006 и 1007. Есть примеры завершённых задач, будущих задач, задач контактов и закрытых сделок.

Все данные вымышлены. Время проверки задано в примере, поэтому результат демо не меняется со временем.

## Подключение amoCRM

Задайте переменные окружения:

- `AMO_SUBDOMAIN` — поддомен аккаунта, без протокола и `.amocrm.ru`;
- `AMO_ACCESS_TOKEN` — действующий access token.

```bash
python -m citycar_case --live
```

Можно записать результат в файл:

```bash
python -m citycar_case --live --output output/report.json
```

Код отправляет только GET-запросы. Он не создаёт задачи и не меняет сделки. Токен не записывается в отчёт.

Обновление OAuth-токена в примере не реализовано: для live-режима нужен действующий токен.

## Что считается проблемой

«Без задач» — у открытой сделки нет незавершённой задачи, привязанной непосредственно к этой сделке.

«Просрочка» — у сделки есть незавершённая задача с дедлайном раньше времени проверки. Будущая задача не отменяет уже существующую просрочку.

Статусы 142 и 143 исключаются. Задачи контактов и компаний не подменяют задачи сделки: для этого потребуется отдельное правило связывания.

API-клиент учитывает пагинацию, ответ 204, ограничение частоты запросов и ограниченные повторы при 429 и временных ошибках сервера. Если выгрузка не завершилась, результат не выдаётся как полный.

## Ограничения

Это текущий срез доступных интеграции сделок. Последовательные API-запросы не дают атомарного снимка CRM.

Для внедрения нужно проверить права интеграции и полноту данных, добавить обновление токенов, общий лимитер для нескольких процессов и журналирование. Историю работы за 30 дней следует считать по событиям, а не восстанавливать из текущих статусов.

## Файлы

- `citycar_case/amo.py` — API-клиент;
- `citycar_case/rules.py` — правила поиска проблемных сделок;
- `citycar_case/__main__.py` — запуск demo и live;
- `examples/demo.json` — учебные данные;
- `examples/amo_excerpt.py` — самостоятельный пример до 50 строк;
- `tests/test_case.py` — проверки правил, API-клиента и запуска;
- `docs/` — ответ на тестовое и схема решения.
